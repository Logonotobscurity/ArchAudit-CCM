# Architecture Realism Validation — November 2026

Deep research against current continuous control monitoring practice (ServiceNow IRM agentic CCM, Drata, TrustCloud, ISO 42001 Clause 9) and deterministic policy enforcement patterns.

## Market alignment

| Market pattern (2026) | ArchAudit CCM implementation | Realism |
|-----------------------|------------------------------|---------|
| Closed-loop: fail → ticket/action → verify → close | Explicit ActionRecord emission + verification loop (verified / still_failing) on next run | Strong |
| Evidence always-current, not assembled for audit | Typed EvidenceRecord + content hash + hash-chain root written into every audit pack | Strong |
| Policy-gated actions, not opaque agents | Actions remain explicit records; dual-control exceptions; no agent loop in the action plane | Differentiator |
| Deterministic evaluation preferred for auditability | Rule evaluator is pure and replayable; decision_basis recorded | Strong |
| Regional / localisation constraints | Pure YAML overlays (NG, KE, ZA, GH) + offline-replayable packs | Strong (Africa edge) |
| Integrations (webhook, ticket, API) | Outbound stubs + live adapter paths with offline fallback | Good for MVP |

## ISO 42001 Clause 9 fit

- Clause 9.1 requires determining what to monitor, methods that produce valid (comparable, reproducible) results, and documented evidence of results.
- ArchAudit produces reproducible metrics, hash-chain roots, decision logs, and OSCAL Assessment Results on every run.
- Operating evidence (not just documentary) is generated by the pipeline itself.

## Deterministic vs agentic

2026 guidance (Vaikora, Workato, NHI Mgmt, IBM) consistently places deterministic policy enforcement at the execution boundary for any action with material blast radius. Agentic interpretation is allowed for analysis; execution must be policy-gated and reproducible.

ArchAudit keeps evaluation and action emission deterministic and explicit. This matches the recommended split and avoids the opacity risk of pure agentic CCM loops.

## Gaps relative to full enterprise platforms

- Live adapter coverage is still minimal (two working paths + stubs).
- No full ITSM/ticketing integration yet (stubs only).
- Metrics surface is static HTML, not a real-time dashboard.
- Signing is a placeholder, not production PKI.

These are intentional for an offline-first, evidence-native vertical slice. The architecture is realistic for its scope and aligned with 2026 closed-loop CCM expectations while preserving auditability and localisation advantages.

## Conclusion

The implementation is realistic as a focused, evidence-native, offline-replayable CCM system. It matches the closed-loop pattern ServiceNow and others are productising, while deliberately staying deterministic and explicit where the market is still resolving agentic opacity risks. Suitable as a credible foundation for further live integrations and regional expansion.
